## ConcurrentModificationException là gì?

**ConcurrentModificationException (CME)** là một lỗi runtime xảy ra khi bạn **thay đổi cấu trúc của collection** (thêm, xóa phần tử) trong khi đang **duyệt (iterate)** qua nó. Đây là một trong những lỗi phổ biến nhất khi làm việc với `List`, `Set`, và `Map` trong Java.

Hãy tưởng tượng bạn đang **đọc danh sách học sinh** trong lớp (iterate), đồng thời bạn khác đang **xóa tên học sinh** khỏi danh sách (modify). Khi bạn đọc đến tên đã bị xóa, mọi thứ trở nên hỗn loạn -- đó chính là `ConcurrentModificationException`.

Lưu ý: Tên là "Concurrent" nhưng lỗi này **không chỉ xảy ra trong multi-thread**. Nó hoàn toàn có thể xảy ra trong **cùng một thread** nếu bạn modify collection trong khi đang for-each.

## 1. Demo lỗi: Remove trong for-each

```java
import java.util.ArrayList;
import java.util.List;

public class CmeDemo {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");
        fruits.add("Date");

        // ❌ Loi: Remove trong for-each
        try {
            for (String fruit : fruits) {
                if (fruit.startsWith("B")) {
                    fruits.remove(fruit); // ConcurrentModificationException!
                }
            }
        } catch (java.util.ConcurrentModificationException e) {
            System.out.println("Loi: " + e.getClass().getSimpleName());
        }
    }
}
```

**Tại sao lỗi?** Vòng for-each sử dụng `Iterator` phía sau. Khi bạn gọi `fruits.remove()` trực tiếp (không qua Iterator), Iterator phát hiện collection đã bị thay đổi và throw `ConcurrentModificationException`.

## 2. Nguyên nhân chi tiết: Fail-fast Iterator

Java sử dụng cơ chế **fail-fast** cho Iterator của các collection như `ArrayList`, `HashMap`, `HashSet`:

```java
import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class FailFastDemo {
    public static void main(String[] args) {
        List<Integer> numbers = new ArrayList<>(List.of(1, 2, 3, 4, 5));

        // ❌ Loi: Goi collection.remove() trong khi dang iterate
        try {
            Iterator<Integer> it = numbers.iterator();
            while (it.hasNext()) {
                Integer num = it.next();
                if (num == 3) {
                    numbers.remove(num); // Goi tren COLLECTION, khong phai Iterator
                    // -> ConcurrentModificationException
                }
            }
        } catch (java.util.ConcurrentModificationException e) {
            System.out.println("Fail-fast: " + e.getClass().getSimpleName());
        }
    }
}
```

**Cơ chế hoạt động:**
- Iterator giữ một biến `expectedModCount` = `modCount` của collection.
- Mỗi khi `add()` hoặc `remove()` trên collection, `modCount` tăng lên.
- Khi `iterator.next()` được gọi, nó kiểm tra `modCount != expectedModCount` -> throw CME.
- Chỉ có `Iterator.remove()` mới đồng bộ được `expectedModCount` với `modCount`.

## 3. Cách khắc phục (4 cách)

### Cách 1: Dùng Iterator.remove()

```java
import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class FixWithIterator {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");
        fruits.add("Date");

        // ✅ Dung: Su dung Iterator.remove()
        Iterator<String> it = fruits.iterator();
        while (it.hasNext()) {
            String fruit = it.next();
            if (fruit.startsWith("B")) {
                it.remove(); // An toan! Iterator tu dong dong bo modCount
            }
        }

        System.out.println(fruits); // [Apple, Cherry, Date]
    }
}
```

**Ưu điểm:** Đơn giản, hoạt động với mọi phiên bản Java.
**Nhược điểm:** Chỉ hỗ trợ `remove()`, không hỗ trợ `add()`.

### Cách 2: Dùng removeIf() (Java 8+)

```java
import java.util.ArrayList;
import java.util.List;

public class FixWithRemoveIf {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");
        fruits.add("Blueberry");

        // ✅ Dung: removeIf (Java 8+) -- gon nhat
        fruits.removeIf(fruit -> fruit.startsWith("B"));

        System.out.println(fruits); // [Apple, Cherry]
    }
}
```

**Ưu điểm:** Gọn gàng, đọc hiểu dễ dàng, an toàn.
**Nhược điểm:** Chỉ hỗ trợ **xóa** theo điều kiện, không hỗ trợ thêm hay sửa.

### Cách 3: Copy collection rồi modify

```java
import java.util.ArrayList;
import java.util.List;

public class FixWithCopy {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");

        // ✅ Dung: Duyet ban copy, modify ban goc
        List<String> toRemove = new ArrayList<>();

        for (String fruit : fruits) {
            if (fruit.startsWith("B")) {
                toRemove.add(fruit); // Ghi nho phan tu can xoa
            }
        }

        fruits.removeAll(toRemove); // Xoa sau khi duyet xong

        System.out.println(fruits); // [Apple, Cherry]
    }
}
```

**Hoặc duyệt bản copy:**

```java
import java.util.ArrayList;
import java.util.List;

public class FixWithCopy2 {
    public static void main(String[] args) {
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");

        // ✅ Duyet ban copy (new ArrayList), modify ban goc
        for (String fruit : new ArrayList<>(fruits)) {
            if (fruit.startsWith("B")) {
                fruits.remove(fruit); // An toan vi dang duyet ban copy
            }
        }

        System.out.println(fruits); // [Apple, Cherry]
    }
}
```

**Ưu điểm:** Linh hoạt, có thể thêm/xóa/sửa tự do.
**Nhược điểm:** Tốn thêm bộ nhớ do tạo bản copy.

### Cách 4: Dùng CopyOnWriteArrayList (thread-safe)

```java
import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;

public class FixWithCOWList {
    public static void main(String[] args) {
        List<String> fruits = new CopyOnWriteArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");

        // ✅ An toan: CopyOnWriteArrayList khong throw CME
        for (String fruit : fruits) {
            if (fruit.startsWith("B")) {
                fruits.remove(fruit); // Khong loi!
            }
        }

        System.out.println(fruits); // [Apple, Cherry]
    }
}
```

**Ưu điểm:** Thread-safe, không bao giờ throw CME.
**Nhược điểm:** Mỗi lần `add()`/`remove()` đều **copy toàn bộ mảng**, rất chậm với collection lớn hoặc ghi nhiều.

## 4. Fail-fast vs Fail-safe Iterator

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.Iterator;

public class FailFastVsFailSafe {
    public static void main(String[] args) {
        // === Fail-fast: ArrayList, HashMap, HashSet... ===
        List<String> failFast = new ArrayList<>(List.of("A", "B", "C"));
        try {
            for (String s : failFast) {
                failFast.add("D"); // ConcurrentModificationException!
            }
        } catch (java.util.ConcurrentModificationException e) {
            System.out.println("Fail-fast: Loi ngay khi modify!");
        }

        // === Fail-safe: CopyOnWriteArrayList, ConcurrentHashMap... ===
        List<String> failSafe = new CopyOnWriteArrayList<>(List.of("A", "B", "C"));
        for (String s : failSafe) {
            failSafe.add("D"); // Khong loi!
        }
        System.out.println("Fail-safe: " + failSafe);
        // [A, B, C, D, D, D] -- Iterator duyet ban snapshot cu
    }
}
```

**So sánh:**

| Đặc điểm | Fail-fast | Fail-safe |
|----------|-----------|-----------|
| **Throw CME** | Có | Không |
| **Iterate trên** | Collection gốc | Bản copy (snapshot) |
| **Bộ nhớ** | Ít | Nhiều (do copy) |
| **Ví dụ** | ArrayList, HashMap, HashSet | CopyOnWriteArrayList, ConcurrentHashMap |
| **Sử dụng** | Single-thread | Multi-thread |

## Khi nào dùng?

| Tình huống | Giải pháp khuyên dùng |
|------------|----------------------|
| Xóa phần tử khi iterate (single-thread) | `Iterator.remove()` hoặc `removeIf()` |
| Xóa nhiều phần tử theo điều kiện | `removeIf()` (Java 8+) |
| Cần thêm phần tử khi iterate | Copy collection rồi modify |
| Multi-thread truy cập collection | `CopyOnWriteArrayList`, `ConcurrentHashMap` |
| Đọc nhiều, ghi ít (multi-thread) | `CopyOnWriteArrayList` |
| Đọc ít, ghi nhiều (multi-thread) | `Collections.synchronizedList()` + synchronized block |

**Best practices:**
- **Mặc định dùng `removeIf()`** (Java 8+) -- gọn nhất và an toàn.
- Dùng `Iterator.remove()` khi cần kiểm soát logic phức tạp hơn.
- Chỉ dùng `CopyOnWriteArrayList` khi **thật sự cần** thread-safety và **đọc nhiều hơn ghi**.
- Không bao giờ gọi `collection.remove()` trực tiếp trong for-each.

```java
// ❌ Sai: Goi remove() tren collection trong for-each
for (String item : list) {
    if (item.equals("delete-me")) {
        list.remove(item); // ConcurrentModificationException!
    }
}
```

```java
// ✅ Dung: Dung removeIf()

```

### Lỗi 2: Nhầm lẫn Iterator.remove() và Collection.remove()

```java
// ❌ Sai: Dung collection.remove() thay vi iterator.remove()
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String item = it.next();
    list.remove(item);  // Goi tren COLLECTION -> CME!
}
```

```java
// ✅ Dung: Dung it.remove() (goi tren ITERATOR)
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String item = it.next();
    if (shouldRemove(item)) {
        it.remove();  // Goi tren ITERATOR -> An toan!
    }
}
```

List<String> bigList = new CopyOnWriteArrayList<>();

## Câu hỏi phỏng vấn

### Câu 1: Tại sao for-each throw ConcurrentModificationException?

**Trả lời:** Vòng for-each trong Java được compiler chuyển thành code sử dụng `Iterator`. Iterator của các collection chuẩn (ArrayList, HashMap...) sử dụng cơ chế **fail-fast**: nó lưu giá trị `expectedModCount` tại thời điểm tạo Iterator. Mỗi khi gọi `next()`, Iterator kiểm tra xem `modCount` của collection có bằng `expectedModCount` không. Nếu collection bị modify (add/remove) trực tiếp (không qua Iterator), `modCount` thay đổi nhưng `expectedModCount` không cập nhật -> Iterator phát hiện và throw CME.

### Câu 2: Iterator.remove() khác gì Collection.remove()?

**Trả lời:**
- **Iterator.remove()**: Xóa phần tử vừa được trả về bởi `next()`. Sau khi xóa, nó **cập nhật `expectedModCount`** để đồng bộ với `modCount` của collection. Do đó không gây CME.
- **Collection.remove()**: Xóa trực tiếp trên collection. Chỉ tăng `modCount` mà **không cập nhật `expectedModCount`** của Iterator đang chạy. Khi Iterator gọi `next()`, nó phát hiện `modCount != expectedModCount` và throw CME.

### Câu 3: CopyOnWriteArrayList hoạt động như thế nào?

**Trả lời:** `CopyOnWriteArrayList` lưu trữ dữ liệu trong một mảng internal. Mỗi khi có thao tác **ghi** (add, set, remove), nó:
1. Tạo một **bản copy mới** của toàn bộ mảng.
2. Thực hiện thay đổi trên bản copy.
3. Cập nhật reference sang mảng mới.

Iterator được tạo sẽ duyệt trên **snapshot** (bản sao tại thời điểm tạo Iterator), nên không bị ảnh hưởng bởi các thay đổi sau đó -> không bao giờ throw CME.

**Trade-off:** An toàn với concurrent, nhưng **chậm khi ghi** (vì phải copy toàn bộ mảng). Phù hợp khi **đọc nhiều, ghi ít**.

### Câu 4: Fail-fast là gì? Khác gì fail-safe?

**Trả lời:**
- **Fail-fast**: Iterator phát hiện thay đổi trên collection và **throw CME ngay lập tức**. Mục đích là báo lỗi sớm để tránh kết quả không chính xác. Ví dụ: `ArrayList.iterator()`, `HashMap.keySet().iterator()`.
- **Fail-safe**: Iterator làm việc trên **bản copy** của collection, nên không phát hiện thay đổi và **không bao giờ throw CME**. Ví dụ: `CopyOnWriteArrayList.iterator()`, `ConcurrentHashMap.keySet().iterator()`.

**Lưu ý:** "Fail-safe" không phải thuật ngữ chính thức trong Java spec. Java chỉ định nghĩa "fail-fast". Các collection trong `java.util.concurrent` được gọi là **weakly consistent** (nhất quán yếu).
